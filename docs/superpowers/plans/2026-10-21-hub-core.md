# Hub Core Implementation Plan (plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn mcpsmith's MCP server into a live hub: plans become working tools in the running session (no codegen), with value transforms, keychain secrets, a shared Chrome for recording and browser-session auth, and REA scenario import.

**Architecture:** A plan interpreter builds tool functions with real signatures on top of the existing `mcpsmith.runtime.Api` + `shape`, so hub tools behave exactly like generated servers. Connections persist under `~/.mcpsmith/` and are loaded at server start. A small CDP client talks to one shared Chrome (launched by `mcpsmith browser`) to record traffic into HAR and to read session cookies at call time.

**Tech Stack:** Python ≥3.10, `mcp` 2.x (`MCPServer`, `Context.notify_tools_changed`), httpx, pydantic, `websockets` (CDP), `keyring` (secrets), `tzdata` (zoneinfo on Windows). Tests: pytest + anyio, httpx.MockTransport, a fake CDP websocket server.

**Spec:** `docs/superpowers/specs/2026-10-20-mcp-everything-design.md` (goals G1–G5, G7, G8; decisions 5, 7, 12, 14; "Settled after design review"). Plans 2 (setup bundle, G6) and 3 (app path, G9) follow.

## Global Constraints

- Existing behaviour stays: CLI commands, `generate`, generated servers, 0.1.x plans all keep working; full existing suite stays green.
- No password, cookie, token or secret is written to disk by mcpsmith, put in a plan/fixture, or returned to the agent.
- `smith_call` never executes a tool with `read_only: false`.
- Default timezone is the system's local zone; Jalali is one optional transform, not a default.
- Hub data root: `~/.mcpsmith/` (override with env `MCPSMITH_HOME`): `connections/<name>/{plan.yaml,source.json,meta.json}`, `work/<name>/`, `chrome-profile/`, `browser.json`.
- New dependencies only: `websockets>=12`, `keyring>=25`, `tzdata>=2024.1; sys_platform == "win32"`. No Playwright in this plan.
- Every plan is validated (`design.validate`, errors block) before the interpreter or codegen touches it.
- Code style matches the repo: small modules, short docstrings, comments only for non-obvious why; ruff clean (`uv run ruff check .`, `uv run ruff format --check .`).
- Commit after each task on branch `feat/hub` (never on `main`); no Claude attribution in commits.

## Review Focus

1. Chrome closed or session expired mid-session → a hub tool returns a ToolError naming the fix (`mcpsmith browser` / "log in again in the mcpsmith Chrome window"), never a traceback or a silent empty result. (Task 7 tests.)
2. Two connections defining the same tool name, or a connection tool clashing with `smith_*` → `smith_connect` refuses with the clashing names; existing tools untouched. (Task 8 test.)
3. Jalali calendar edges (leap-year Esfand 30, 1403/12/30 → 2025-03-20, Nowruz boundary) and end-of-day in a non-UTC zone. (Task 2 tests.)
4. A new tab opened by Chrome DevTools MCP after `smith_record_start` → its requests are recorded too. (Task 6 test with the fake CDP server.)
5. A corrupted or invalid saved connection → hub still starts, skips it with a warning in `smith_connections`, others load. (Task 8 test.)
